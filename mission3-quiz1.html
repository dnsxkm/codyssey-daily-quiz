# 과제3 · 데일리 퀴즈 ① (난이도 하)

🔢 부동소수점의 함정 — 왜 0.1 + 0.2 ≠ 0.3?

과제3(NPU 시뮬레이터)의 핵심은 소수(부동소수점) 비교예요. 컴퓨터가 소수를 다룰 때 생기는 미세한 오차 때문에, 점수를 비교하거나 동점을 판정할 때 특별한 방법이 필요하거든요. 맛보기로 6문제(총 7칸) 풀어보세요 — 출력 예측 위주라 감 잡기 좋아요.

문제 1 출력 예측
이 코드의 출력은?
print(0.1 + 0.2 == 0.3)
정답: False. 컴퓨터는 0.1, 0.2 같은 소수를 2진수로 정확히 표현하지 못해서 아주 미세한 오차가 생겨요. 그래서 0.1 + 0.2는 딱 0.3이 아니라 0.30000000000000004가 되고, == 0.3은 False가 됩니다. 이게 부동소수점의 함정이에요.
문제 2 출력 예측
그럼 이건 뭐라고 출력될까요?
print(0.1 + 0.2)
정답: 0.30000000000000004. 문제 1에서 말한 미세한 오차가 실제로 이렇게 눈에 보여요. 오차는 아주 작지만 0은 아니라서, 소수끼리 ==로 비교하면 안 되는 이유가 바로 이겁니다.
문제 3 개념
두 소수 a, b가 사실상 같은지 안전하게 비교하려면?
정답: 2번. 소수는 오차가 있으니 "정확히 같은지"(==) 대신, 두 값의 차이(abs(a - b))가 아주 작은 기준값(EPSILON, 예: 1e-9)보다 작으면 "같다"고 판단해요. 이게 네가 과제3에서 쓴 방식이야.
문제 4 출력 예측
EPSILON 방식으로 비교하면? 출력은?
EPSILON = 1e-9
a = 0.1 + 0.2
b = 0.3
print(abs(a - b) < EPSILON)
정답: True. a와 b의 차이는 약 0.00000000000000004로, EPSILON(0.000000001)보다 훨씬 작아요. 그래서 "사실상 같다"고 판단 → True. ==로는 False였지만 EPSILON 방식으론 True — 이 한 끗 차이가 과제3의 핵심이에요.

문제 6 개념
최고 점수가 두 개 이상 사실상 같을 때(동점)를 감지하려면?
정답: 2번. 동점 판정도 결국 소수 비교라, == 대신 EPSILON을 써서 "차이가 거의 없으면 동점"으로 처리해요. 문제 3~4와 완전히 같은 원리 — 과제3에서 동점 감지에 EPSILON을 쓴 이유입니다.
빈칸 정답은 대소문자·공백에 관계없이 채점돼요.
