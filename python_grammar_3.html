# 파이썬 심화 · 데일리 퀴즈

🔥 동작 원리 파고들기

문법을 아는 것과 왜 그렇게 동작하는지를 아는 건 다릅니다. 여기 있는 12문제는 경력자도 자주 틀리는 것들이에요 — 객체와 참조, 가변성, 스코프, 진리값 판정. 찍으면 거의 틀립니다. 실제로 파이썬에 돌려 검증한 결과만 담았어요.

▚ PART 1 · 객체와 참조

변수는 값을 담는 상자가 아니라, 객체에 붙인 이름표.

문제 1 가변성
튜플은 수정할 수 없다고 했는데… 출력은?
t = ([1, 2], 3)
t[0].append(9)
print(t)
정답: ([1, 2, 9], 3). 튜플이 "못 바꾼다"는 건 어떤 객체를 가리키는지를 못 바꾼다는 뜻이에요. 그 안에 든 리스트 자체는 여전히 가변이라 append가 먹힙니다. 반면 t[1] = 5처럼 칸을 다른 객체로 갈아끼우는 건 TypeError. "튜플은 이름표 목록이 고정될 뿐, 가리키는 대상의 내용까지 얼리지는 않는다"고 기억하세요.
문제 2 곱셈 복사
3×3 격자를 만들려 했어요. 출력은?
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)
정답: 세 줄 모두 바뀝니다. 바깥 * 3은 리스트를 세 개 만드는 게 아니라, 같은 리스트 하나를 가리키는 이름표를 3개 늘어놓아요. 그래서 한 줄을 고치면 세 줄이 다 바뀐 것처럼 보입니다. 올바른 방법은 [[0]*3 for _ in range(3)] — 컴프리헨션은 매번 새 리스트를 만들어요. 2차원 배열 만들 때 가장 흔한 버그입니다.
문제 3 인자 전달
함수가 원본을 바꿀까요? 출력은?
def add_one(lst):
lst.append(1)
 
def replace(lst):
lst = [99]
 
a = []
b = []
add_one(a)
replace(b)
print(a, b)
정답: [1] []. 두 함수의 차이가 핵심이에요. append는 넘겨받은 객체 자체를 수정하니 밖에서도 보입니다. 반면 lst = [99]는 함수 안의 이름표를 새 리스트로 옮겨 붙이는 것일 뿐, 밖의 b는 원래 객체를 계속 가리켜요. "내용을 바꾸면 전달되고, 이름을 갈아끼우면 전달되지 않는다"가 파이썬 인자 전달의 핵심입니다.
▚ PART 2 · 반복과 스코프

언제 값이 정해지는가.

문제 4 반복 중 수정
짝수를 모두 지우려 했어요. 출력은?
nums = [1, 2, 3, 4, 5, 6]
for n in nums:
if n % 2 == 0:
nums.remove(n)
print(nums)
정답: 2번. 이 코드는 실제로 [1, 3, 5]를 출력하지만 운이 좋았을 뿐이에요. for문은 내부적으로 위치(인덱스)로 순회하는데, 원소를 지우면 뒤 원소들이 앞으로 당겨져 한 칸씩 건너뛰게 됩니다. 예를 들어 [1,2,4,5]로 해보면 4가 살아남아요. 그래서 반복하는 리스트를 그 안에서 수정하면 안 되고, nums = [n for n in nums if n % 2]처럼 새 리스트를 만들어야 합니다.
문제 5 늦은 바인딩
함수 3개를 만들어 각각 호출했어요. 출력은?
fs = [lambda: i for i in range(3)]
print([fn() for fn in fs])
정답: [2, 2, 2]. lambda 안의 i는 만들 때가 아니라 호출할 때 값을 찾아봐요(늦은 바인딩). 함수들을 다 만든 뒤엔 i가 이미 마지막 값 2가 되어 있어서, 셋 다 2를 돌려줍니다. 해결하려면 lambda i=i: i처럼 기본 인자로 그 순간의 값을 붙잡아 두면 돼요. 반복문 안에서 콜백·이벤트 핸들러를 만들 때 자주 터지는 함정입니다.
문제 6 스코프
출력은?
x = 10
 
def f():
x = 20
 
f()
print(x)
정답: 10. 함수 안에서 x = 20이라고 대입하는 순간, 파이썬은 그것을 새로운 지역 변수로 취급해요. 밖의 x와는 이름만 같을 뿐 완전히 별개입니다. 전역 x를 진짜로 바꾸려면 함수 안에 global x를 선언해야 해요. (그런데 전역 변수를 바꾸는 건 추적이 어려워지니, 값을 return으로 돌려주는 편이 낫습니다.)
▚ PART 3 · 진리값과 자료구조

파이썬이 참·거짓을 판단하는 방식.

문제 7 진리값
다음 중 if에서 참(True)으로 취급되는 것은?
정답: "False". 파이썬은 비어 있으면 거짓으로 봐요 — 0, 0.0, "", [], {}, None이 모두 거짓입니다. 반면 "False"는 글자가 5개나 든 문자열이라 참이에요. 내용이 "False"라는 건 상관없습니다. 그래서 input()으로 받은 "0"도 참이 되니 주의해야 해요.
문제 8 or 연산
or는 True/False만 돌려줄까요? 출력은?
print([] or "기본값")
정답: 기본값. 파이썬의 or는 True/False가 아니라 피연산자 중 하나를 그대로 돌려줘요. 왼쪽이 거짓이면 오른쪽을, 왼쪽이 참이면 왼쪽을 반환합니다. 그래서 name = 입력값 or "손님"처럼 기본값을 주는 관용구로 자주 쓰여요. 단, 0이 유효한 값인 경우엔 0도 거짓이라 의도치 않게 기본값으로 넘어가니 주의해야 합니다.
문제 9 딕셔너리 키
키가 3개인 줄 알았는데… 출력은?
d = {1: "a", True: "b", 1.0: "c"}
print(len(d))
정답: 1. 파이썬에서 1 == True == 1.0이 모두 참이고, 딕셔너리는 값이 같으면 같은 키로 취급해요. 그래서 세 번 다 같은 칸에 덮어써져 최종 값은 마지막인 "c", 길이는 1입니다. True가 내부적으로 정수 1이라는 점이 놀라운 부분이죠 — True + True == 2도 성립합니다.
문제 10 음수 나눗셈
-7 // 2 의 결과는?
정답: -4. //는 "소수점 버림"이 아니라 더 작은 쪽(음의 무한대 방향)으로 내림이에요. -3.5를 내리면 -3이 아니라 -4가 됩니다. 양수일 땐 둘이 같아서 헷갈리지 않지만, 음수에서 차이가 드러나요. 0쪽으로 자르고 싶다면 int(-7 / 2)를 쓰면 -3이 됩니다.
▚ PART 4 · 함수와 반환

무엇이 돌아오는가.

문제 11 제자리 연산
출력은?
nums = [3, 1, 2]
result = nums.sort()
print(result, nums)
정답: None [1, 2, 3]. .sort()는 리스트를 제자리에서 정렬하고 반환값은 None이에요. 그래서 result엔 None이 담기지만 nums 자체는 정렬됩니다. random.shuffle(), .append(), .reverse()도 같은 패턴이에요. 새 리스트를 받고 싶다면 sorted(nums)를 쓰세요. "제자리에서 바꾸는 것은 None을 돌려준다"가 파이썬의 일관된 규칙입니다.
문제 12 문자열 불변
출력은?
s = "hello"
s.upper()
print(s)
정답: hello. 문자열은 불변(immutable)이라 어떤 메서드도 원본을 바꾸지 못해요. upper()는 대문자로 바꾼 새 문자열을 돌려줄 뿐이라, 받아두지 않으면 그냥 버려집니다. s = s.upper()처럼 다시 대입해야 해요. 같은 이유로 s[0] = "H"도 TypeError가 납니다. 리스트(가변)와 정반대라 헷갈리기 쉬워요.
