▚ 주제 1 · 딕셔너리

{키: 값} 짝으로 저장하는 그릇.

문제 1 기본
출력은?
d = {"a": 1, "b": 2}
d["a"] = 9
d["c"] = 3
print(len(d))
정답: 3. 딕셔너리에서 대괄호 대입은 키가 있으면 덮어쓰고, 없으면 새로 만들어요. d["a"] = 9는 이미 있는 키라 값만 1→9로 바뀌고 개수는 그대로. d["c"] = 3은 새 키라 하나 늘어나서 최종 3개입니다.
문제 2 get
d = {"a": 1} 일 때 없는 키를 꺼내는 두 방법의 차이는?
정답: 2번. 대괄호는 없는 키에 엄격해서 KeyError로 프로그램이 멈춰요. .get()은 관대해서 None을 돌려주고, d.get("z", 0)처럼 기본값도 지정할 수 있습니다. "반드시 있어야 하는 키"엔 대괄호를, "없을 수도 있는 키"엔 get을 쓰면 됩니다.
문제 3 개수 세기
글자 개수를 세는 코드예요. 빈칸에 들어갈 것은?
count = {}
for ch in "hello":
count[ch] = count.(ch, 0) + 1
print(count) # {'h':1,'e':1,'l':2,'o':1}
정답: get. 처음 보는 글자는 아직 키가 없어서 count[ch]로 바로 읽으면 KeyError가 나요. get(ch, 0)은 없으면 0에서 시작하게 해줍니다. 그래서 첫 등장은 0+1=1, 두 번째 등장은 1+1=2가 되죠. 개수 세기의 정석 관용구라 외워두면 좋아요.
▚ 주제 2 · 클래스 / 객체

틀(class)로 실물(객체)을 찍어낸다.

문제 4 개념
클래스와 객체(인스턴스)의 관계로 가장 알맞은 비유는?
정답: 2번. class Dog:는 설계도일 뿐 실물이 아니에요. a = Dog("초코")라고 해야 비로소 객체가 만들어집니다. 틀 하나로 붕어빵을 여러 개 찍듯, 클래스 하나로 객체를 여러 개 만들 수 있고 각각은 서로 다른 값을 가져요.
문제 5 __init__
__init__ 메서드에 대한 설명으로 옳은 것은?
정답: 2번. Dog("초코")라고 쓰는 순간 파이썬이 알아서 __init__을 실행해 초기 상태를 준비해요. 그래서 생성자라고 부릅니다. 없어도 클래스는 만들어지지만, 그러면 객체마다 다른 값을 넣어줄 수 없어요.
문제 6 출력 예측
객체 두 개를 만들었어요. 출력은?
class Dog:
def __init__(self, name):
self.name = name
 
a = Dog("초코")
b = Dog("보리")
print(a.name, b.name)
정답: 초코 보리. self.name은 객체마다 따로 저장되는 값(인스턴스 속성)이에요. a와 b는 같은 클래스로 만들었어도 완전히 별개의 객체라, 각자의 이름을 갖습니다. 이게 클래스를 쓰는 핵심 이유예요 — 같은 구조, 다른 데이터.
▚ 주제 3 · self

"이 객체 자신"을 가리키는 이름.

문제 7 개념
메서드의 첫 번째 매개변수 self는 무엇을 가리킬까요?
정답: 2번. a.bark()라고 쓰면 파이썬이 내부적으로 Dog.bark(a)처럼 a를 self 자리에 넣어줘요. 그래서 메서드 안에서 self.name이라고 하면 "지금 이 객체의 이름"이 됩니다. 이름이 꼭 self여야 하는 건 아니지만, 모두가 그렇게 쓰는 약속이라 지키는 게 좋아요.
문제 8 함정
self를 빼먹었어요. 실행하면?
class Cat:
def meow():
print("야옹")
 
Cat().meow()
정답: TypeError. Cat().meow()는 인자를 안 넘긴 것처럼 보이지만, 파이썬이 자동으로 객체 자신을 첫 인자로 넣어줘요. meow()는 매개변수를 하나도 안 받게 정의됐으니 "0개를 받는데 1개가 왔다"며 오류가 납니다. 그래서 메서드엔 항상 self를 적어야 해요.
▚ 주제 4 · self.xxx vs xxx

점 하나 차이가 만드는 결과.

문제 9 함정
self.를 빠뜨렸어요. 실행하면?
class Counter:
def __init__(self):
count = 0 # self. 없음!
 
def bump(self):
self.count += 1
 
c = Counter()
c.bump()
정답: AttributeError. __init__ 안의 count = 0은 그냥 지역 변수라, 함수가 끝나면 사라져요. 객체엔 아무것도 저장되지 않습니다. 그래서 bump()에서 self.count를 찾을 때 "그런 속성 없음"이라며 오류가 나요. self.count = 0으로 고쳐야 합니다.
문제 10 빈칸
두 빈칸에 각각 name 과 self.name 중 알맞은 것을 쓰세요.
class Person:
def __init__(self, name):
self.name =
 
def greet(self):
return "안녕, " +
정답: name, self.name. 첫 번째는 밖에서 받은 매개변수 name을 객체에 저장하는 자리예요 — 오른쪽에 self.name을 쓰면 아직 없는 값을 참조해 에러가 납니다. 두 번째 greet()에는 name이라는 지역 변수가 없으니, 저장해둔 self.name을 꺼내 써야 해요. "받을 땐 name, 꺼낼 땐 self.name"으로 기억하세요.
문제 11 클래스 속성
클래스 몸통에 쓴 것과 self.로 만든 것의 차이는? 출력은?
class Box:
shared = []
def __init__(self):
self.own = []
 
a = Box(); b = Box()
a.shared.append(1)
a.own.append(1)
print(b.shared, b.own)
정답: [1] []. shared는 클래스에 하나만 있어서 모든 객체가 같이 씁니다. a가 넣은 1이 b에도 보이죠. 반면 self.own은 __init__에서 객체마다 새로 만들어지니 b의 것은 여전히 비어 있어요. 객체별로 따로 관리할 값이면 반드시 self.를 붙여야 합니다.
▚ 주제 5 · json

파이썬 데이터를 파일로, 파일을 다시 데이터로.

문제 12 4가지 함수
파이썬 딕셔너리를 파일에 저장할 때 쓰는 함수는?
정답: json.dump(data, f). 네 가지를 표로 외우면 편해요 — 파일에 쓰기는 dump, 파일에서 읽기는 load. 문자열로 바꾸기는 dumps, 문자열에서 읽기는 loads. s가 붙으면 string(문자열)이라고 기억하면 헷갈리지 않습니다.
문제 13 한글
json.dumps({"n": "민수"}) 의 결과는?
정답: 2번 — 한글이 \uXXXX 형태로 바뀝니다. json은 기본적으로 아스키(영문)로만 저장하려 해서 한글을 코드로 변환해요. 읽을 때는 정상으로 돌아오지만 파일을 열어보면 알아볼 수 없죠. json.dumps(data, ensure_ascii=False)를 주면 한글 그대로 저장됩니다. 한글 데이터를 다룬다면 거의 항상 붙여야 하는 옵션이에요.
문제 14 자료형 변화
튜플을 저장했다가 다시 불러오면 어떤 자료형이 될까요?
s = json.dumps({"t": (1, 2)})
back = json.loads(s)
print(back)
정답: 리스트로 바뀝니다. JSON에는 튜플이라는 개념이 없어요. 그래서 저장할 때 배열(리스트)로 바뀌고, 다시 읽으면 리스트로 돌아옵니다. 같은 이유로 딕셔너리의 정수 키도 문자열이 돼요 ({1:"a"} → {"1":"a"}). 저장 후 자료형이 달라질 수 있다는 걸 알아두면 버그를 예방할 수 있어요.
▚ 주제 6 · 예외처리

오류가 나도 죽지 않는 프로그램.

문제 15 출력 예측
출력 순서는?
try:
x = int("5")
except ValueError:
print("A")
else:
print("B")
finally:
print("C")
정답: B 다음 C. int("5")는 성공하니 except는 건너뜁니다. else는 예외가 안 났을 때만 실행돼서 "B", finally는 예외가 나든 안 나든 항상 실행돼서 "C". 만약 int("abc")였다면 A와 C가 나왔을 거예요. finally는 파일 닫기처럼 무슨 일이 있어도 해야 할 뒷정리에 씁니다.
문제 16 구체적 예외
except Exception: 으로 모든 예외를 한꺼번에 잡으면 안 되는 이유는?
정답: 2번. 넓게 잡으면 처리하려던 오류뿐 아니라 변수명 오타(NameError) 같은 진짜 버그까지 조용히 묻혀요. 프로그램은 안 죽지만 잘못된 결과가 나오고, 원인 찾기가 훨씬 어려워집니다. ValueError, KeyError처럼 예상되는 것만 콕 집어 잡는 게 안전해요.
문제 17 예외 짝짓기
int("abc") 를 실행하면 발생하는 예외는?
정답: ValueError. 타입은 맞는데(문자열) 값이 이상할 때 나는 오류예요. 반대로 "3" + 3처럼 타입 자체가 안 맞으면 TypeError입니다. 자주 만나는 것들을 짝지어 두면 좋아요 — 없는 키는 KeyError, 없는 파일은 FileNotFoundError, 0으로 나누면 ZeroDivisionError, 범위 밖 인덱스는 IndexError.
주제별 점수가 함께 표시돼요. 빈칸은 대소문자·공백 무관.
