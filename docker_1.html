# 과제1 · 도커 데일리 퀴즈

🐳 Docker 개념 정리

개발 환경 구축 과제에서 다뤘던 내용이에요. 이미지와 컨테이너의 차이부터 Dockerfile, 포트 매핑, 마운트, 그리고 실제로 자주 터지는 오류까지. 평가 때 나올 만한 것 위주로 17문제 담았습니다.

▚ 주제 1 · 이미지 vs 컨테이너

붕어빵 틀과 붕어빵.

문제 1 핵심 개념
이미지와 컨테이너의 관계로 옳은 것은?
정답: 2번. 붕어빵 틀(이미지)과 붕어빵(컨테이너)으로 생각하면 쉬워요. 틀 하나로 붕어빵을 여러 개 찍듯, 같은 이미지로 컨테이너를 여러 개 띄울 수 있습니다. 또 하나 중요한 차이 — 이미지는 읽기 전용이라 컨테이너 안에서 파일을 고쳐도 이미지는 안 바뀌어요. 그 컨테이너를 지우면 변경사항도 함께 사라집니다.
문제 2 변경의 관점
컨테이너 안에서 파일을 수정한 뒤 그 컨테이너를 삭제하면?
정답: 2번. 컨테이너의 변경사항은 그 컨테이너에만 얹혀 있어요. 삭제하면 같이 없어지고, 이미지로 새로 띄우면 깨끗한 원본 상태입니다. 그래서 데이터를 남기려면 볼륨을 쓰고, 환경 자체를 바꾸려면 Dockerfile을 고쳐 이미지를 다시 빌드해야 해요. 이게 "재현 가능한 환경"의 핵심 원리입니다.
▚ 주제 2 · Dockerfile

나만의 이미지를 만드는 설계도.

문제 3 빈칸
nginx 기반 웹서버 이미지를 만드는 Dockerfile이에요. 빈칸 3곳을 채우세요.
nginx:alpine # 베이스 이미지
index.html /usr/share/nginx/html/
80 # 사용할 포트 명시
정답: FROM, COPY, EXPOSE. FROM은 바닥부터 만들지 않고 기존 이미지 위에서 시작한다는 뜻이에요(nginx가 이미 깔린 상태). COPY는 내 컴퓨터의 파일을 이미지 안으로 복사합니다. EXPOSE는 "이 컨테이너는 80번 포트를 씁니다"라는 문서화·안내예요 — 실제 연결은 실행할 때 -p로 합니다.
문제 4 빌드
docker build -t my-web . 에서 마지막 . 의 의미는?
정답: 2번 — 빌드 컨텍스트. 도커에게 "이 폴더를 기준으로 Dockerfile과 복사할 파일들을 찾아라"라고 알려주는 거예요. 그래서 엉뚱한 디렉토리에서 실행하면 Dockerfile을 못 찾거나 COPY할 파일이 없다고 실패합니다. -t my-web은 만들어질 이미지에 이름표(태그)를 붙이는 옵션이에요.
문제 5 수정 반영
Dockerfile로 만든 이미지에서 index.html 내용을 바꾸고 싶어요. (마운트를 쓰지 않는 경우) 어떻게 해야 반영될까요?
정답: 2번. COPY는 빌드하는 그 순간에 파일을 이미지 안으로 복사해 넣는 거라, 이후 원본을 고쳐도 이미지 안의 사본은 그대로예요. 그래서 docker build를 다시 해야 합니다. 바로 이 불편함 때문에 개발 중에는 다음 주제인 바인드 마운트를 쓰는 거예요 — 빌드 없이 즉시 반영되거든요.
▚ 주제 3 · 포트 매핑

컨테이너 안의 서버에 밖에서 접속하기.

문제 6 방향
docker run -p 8080:80 my-web 에서 8080과 80은 각각 어디의 포트일까요?
정답: 1번 — -p 호스트:컨테이너 순서. 왼쪽이 바깥(내 컴퓨터), 오른쪽이 안(컨테이너)이에요. 그래서 브라우저에서 localhost:8080으로 들어가면 컨테이너의 80번 포트로 연결됩니다. 잠긴 방(컨테이너)에 복도(호스트)에서 들어가는 문을 뚫는 것으로 생각하면 쉬워요. 순서를 바꿔 쓰면 접속이 안 되니 주의.
문제 7 증거
docker ps 출력에 0.0.0.0:8080->80/tcp 라고 나왔어요. 무슨 뜻일까요?
정답: 2번. 화살표가 매핑 방향을 보여줘요 — 호스트 8080 → 컨테이너 80. 앞의 0.0.0.0은 "어느 주소로 들어와도 받는다"는 의미입니다. 평가에서 포트 매핑이 실제로 성립했다는 증거로 이 출력을 보여주면 좋아요.
문제 8 충돌
-p 8080:80 으로 띄우려는데 8080이 이미 사용 중이라 실패했어요. 가장 간단한 해결책은?
정답: 2번. 충돌은 내 컴퓨터(호스트) 쪽에서 나는 거라 왼쪽 숫자만 비켜주면 돼요. 그럼 localhost:8081로 접속합니다. 컨테이너 쪽(오른쪽 80)은 건드리면 안 돼요 — nginx가 실제로 80에서 듣고 있는데 81로 바꾸면 아무도 없는 방에 문을 뚫는 셈이라 연결이 안 됩니다. EXPOSE를 고치는 것도 실제 연결과 무관하고요.
▚ 주제 4 · 바인드 마운트 vs 볼륨

둘 다 파일을 연결하지만 목적이 다르다.

문제 9 바인드 마운트
바인드 마운트로 띄운 뒤 내 폴더의 index.html을 수정했어요. 브라우저를 새로고침하면?
정답: 2번 — 즉시 반영. 바인드 마운트는 내 폴더를 컨테이너 안에 실시간으로 연결하는 거예요. 파일을 복사한 게 아니라 같은 파일을 함께 보는 상태라, 고치면 그대로 보입니다. "빌드 안 했는데 반영됨"이 바로 바인드 마운트의 증거예요. 개발 중 코드를 자주 고칠 때 유용합니다.
문제 10 볼륨
볼륨에 데이터를 저장하고 컨테이너를 삭제한 뒤, 새 컨테이너에 같은 볼륨을 연결하면?
정답: 2번 — 영속성. 볼륨은 컨테이너와 별개로 도커가 관리하는 저장 공간이라, 컨테이너를 지워도 살아남아요. 이게 영속성(persistence)이고, 데이터베이스처럼 사라지면 안 되는 데이터를 다룰 때 필수입니다. "컨테이너 삭제 후에도 데이터가 읽힌다"는 게 평가에서 보여줄 증거예요.
문제 11 차이
바인드 마운트와 볼륨의 가장 큰 차이는?
정답: 2번. 용도로 구분하면 쉬워요 — 바인드 마운트는 내 소스코드를 연결해 개발 중 즉시 반영받는 용도, 볼륨은 DB 데이터처럼 안전하게 오래 보관하는 용도. 바인드 마운트는 내 폴더 구조에 의존해서 다른 컴퓨터에선 경로가 달라질 수 있지만, 볼륨은 도커가 관리해 그런 문제가 없습니다.
▚ 주제 5 · 기본 명령어

상태 확인하고 안으로 들어가기.

문제 12 ps
docker ps 와 docker ps -a 의 차이는?
정답: 2번. -a는 all이에요. 컨테이너를 띄웠다 멈췄는데 docker ps에 안 보인다면 사라진 게 아니라 멈춰 있는 것이라, -a로 봐야 나옵니다. 그리고 멈춘 컨테이너도 이름을 계속 차지하고 있어서, 같은 이름으로 새로 띄우려 하면 충돌이 나요(문제 16 참고).
문제 13 exec vs attach
실행 중인 컨테이너 안에서 새 셸을 열어 작업하려면?
정답: exec. exec는 새 프로세스(셸)를 추가로 실행해서 들어가는 거라, 나올 때 exit해도 컨테이너는 계속 돌아가요. 반면 attach는 이미 돌고 있는 메인 프로세스에 붙는 것이라 거기서 나가면 컨테이너가 멈출 수 있습니다. -it는 키보드 입력이 되는 대화형 터미널을 붙이는 옵션이에요. 참고로 run은 새 컨테이너를 만드는 명령이라 상황이 다릅니다.
문제 14 로그
컨테이너가 자꾸 꺼져요. 왜 죽었는지 확인하려면?
정답: docker logs. 컨테이너가 화면에 출력한 내용을 모아 보여주는 명령이라, 에러 메시지가 여기 남아요. 멈춘 컨테이너의 로그도 볼 수 있습니다. 다른 것들과 구분하면 — stats는 CPU·메모리 실시간 사용량, images는 이미지 목록, info는 도커 전체 환경 정보예요.
▚ 주제 6 · 트러블슈팅

실제로 자주 터지는 오류들.

문제 15 이름 충돌
docker: Error response from daemon: Conflict. The container name "/web" is already in use — 해결책은?
정답: 2번. 컨테이너 이름은 중복될 수 없어요. 그리고 멈춘 컨테이너도 이름을 계속 차지합니다 — docker ps엔 안 보이지만 docker ps -a엔 있죠. 그래서 docker rm web으로 지우고 다시 띄우거나, --name web2로 다른 이름을 주면 됩니다. 실행 중이라면 docker stop web 먼저 하고요.
문제 16 데몬 연결
Cannot connect to the Docker daemon 오류가 났어요. 가장 먼저 확인할 것은?
정답: 2번. 데몬은 실제로 컨테이너를 굴리는 백그라운드 엔진이에요. 터미널의 docker 명령은 그 엔진에 요청을 보내는 창구일 뿐이라, 엔진이 꺼져 있으면 아무것도 안 됩니다. docker --version은 창구만 확인하는 거라 엔진이 꺼져 있어도 잘 나와요 — 그래서 헷갈리기 쉽습니다. 엔진까지 확인하려면 docker info를 쓰세요.
문제 17 -v 문법
바인드 마운트 옵션 중 올바른 형식은?
정답: 2번. -v는 콜론(:)으로 양쪽을 잇는 형식이에요 — -v 내폴더:컨테이너안폴더. 포트 매핑 -p 8080:80과 똑같은 구조라 함께 외우면 좋습니다. 콜론을 빠뜨리거나 공백으로 띄우면 도커가 이름 있는 볼륨으로 오해하거나 오류를 냅니다. $(pwd)는 현재 폴더의 절대경로를 넣어주는 것으로, 상대경로는 안 되기 때문에 씁니다.
주제별 점수가 함께 표시돼요. 빈칸은 대소문자·공백 무관.
