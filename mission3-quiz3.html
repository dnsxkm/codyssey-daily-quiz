이번엔 "돌아가게 만들기"를 넘어 왜 그렇게 설계했는가를 묻습니다. 상대 오차 vs 절대 오차, 필터 설계, 성능 측정의 함정, 데이터 설계까지. 7문제(총 11칸) — 각오하고 푸세요.

문제 1 EPSILON 심화
고정 EPSILON(1e-9) 방식의 한계로 옳은 것은?
정답: 2번. 부동소수점 오차는 값의 크기에 비례해서 커져요. 1e12쯤 되면 오차 자체가 1e-9보다 훨씬 커져서, 사실상 같은 값인데도 "차이가 EPSILON보다 크다"며 동점으로 안 봅니다. 그래서 범용 비교에는 상대 오차를 쓰거나 math.isclose(a, b, rel_tol=1e-9)를 씁니다. 과제3은 점수 범위가 작아 고정 EPSILON으로 충분하지만, 한계를 알고 선택하는 것과 모르고 쓰는 건 달라요.
문제 2 빈칸 · 필터 생성
N×N Cross 필터(가운데 행·열이 1, 나머지 0)를 만드는 함수예요. 빈칸 2곳.
def make_cross(n):
mid = n 2
grid = []
for i in range(n):
row = []
for j in range(n):
hit = (i == mid j == mid)
row.append(1.0 if hit else 0.0)
grid.append(row)

정답: //, or. ① //는 정수 나눗셈. n / 2를 쓰면 5/2 = 2.5(float)가 되어 인덱스로 못 써요. ② Cross(+ 모양)는 가운데 행이거나 가운데 열이면 1이니 or. 만약 and를 쓰면 정중앙 한 칸만 1이 되어 완전히 다른 필터가 됩니다. (참고로 X 모양은 i == j or i + j == n - 1로 대각선을 잡아요.)
문제 3 성능 측정
실행 시간을 잴 때 한 번만 측정하면 안 되는 이유로 가장 적절한 것은?
정답: 2번. 같은 코드를 여러 번 돌려도 시간이 매번 다릅니다 — 다른 프로그램이 CPU를 쓰거나, 캐시 상태가 다르거나 해서요. 그래서 반복 측정 후 평균(또는 최솟값)을 쓰는 게 정석이에요. N=5처럼 빠른 경우는 1회 측정이 측정 오차보다도 짧아서 0에 가깝게 나오기도 합니다. 리포트에 수치를 쓸 땐 몇 회 측정했는지도 밝히면 좋아요.
문제 4 데이터 설계
동점(UNDECIDED) 케이스를 일부러 데이터에 심으려면?
정답: 2번. 0.1을 일곱 번 더하면 정확히 0.7이 아니라 0.7000000000000001이 돼요. 그래서 한쪽엔 0.7 한 칸, 다른 쪽엔 0.1 일곱 칸을 배치하면 사람 눈엔 같은데 컴퓨터엔 미세하게 다른 진짜 부동소수점 동점 케이스가 만들어집니다. 1번(정수로 딱 맞추기)은 오차가 없어 부동소수점 함정을 보여주지 못해요. 주의: 반복 덧셈이 항상 어긋나는 건 아니에요 — 0.1을 여덟·아홉 번 더하면 우연히 0.8, 0.9와 정확히 같아집니다. 그래서 동점 케이스를 설계할 땐 실제로 값을 찍어보고 어긋나는 조합을 골라야 해요.

문제 6 출력 예측
누적 순서에 따른 결과예요. 출력은?
a = 0.1 + 0.1 + 0.1
b = 0.3
print(a == b, abs(a - b) < 1e-9)
정답: False True. 0.1을 세 번 더하면 0.30000000000000004가 되어 == 0.3은 False. 하지만 차이는 약 5.5e-17로 1e-9보다 훨씬 작아서 EPSILON 비교는 True. 같은 두 값을 두고 판정이 갈리는 것 — 이게 MAC처럼 여러 번 누적하는 연산에서 ==를 쓰면 안 되는 이유입니다.
문제 7 복잡도 심화
모드2에서 P개의 패턴을 각각 N×N MAC으로 처리하고, 패턴마다 Cross·X 두 번 계산한다면 전체 복잡도는?
정답: O(P × N²). MAC 한 번이 N² 이고, 패턴마다 2번 하니 2N², 그걸 P개 패턴에 반복하면 P × 2N². 빅오에서 상수 2는 무시하므로 O(P × N²)입니다. 핵심은 두 가지 — 상수배는 빼고, 반복이 중첩되면 곱해진다는 것. 리포트에 "패턴 수에 비례해 선형으로, 격자 크기엔 제곱으로 늘어난다"고 쓰면 정확해요.
빈칸 정답은 대소문자·공백에 관계없이 채점돼요.
